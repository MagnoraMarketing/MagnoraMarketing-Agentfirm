---
title: Render + Supabase
summary: Host Paperclip on Render with a Supabase Postgres database
---

Paperclip is a long-running server (heartbeat scheduler, live UI updates,
agent CLI processes). It does not run on serverless platforms such as Vercel.
Render runs the repo `Dockerfile` as a long-lived container, and Supabase
provides the Postgres database.

## 1. Get the Supabase connection string

In the Supabase project: **Connect → Direct → Connection Method: Session
pooler → Type: URI**. Copy the URI (it ends in `:5432/postgres`) and replace
`[YOUR-PASSWORD]` with the database password.

Use the **Session pooler**, not "Direct connection" (IPv6-only, which Render
cannot reach) and not "Transaction pooler" (needs extra client settings).

## 2. Create the service from the Blueprint

1. Render dashboard → **New → Blueprint**.
2. Pick this GitHub repository and the branch that contains `render.yaml`.
3. Render asks for the `sync: false` values:
   - `DATABASE_URL`: the Session pooler URI from step 1
   - `PAPERCLIP_PUBLIC_URL`: leave a placeholder for now, e.g.
     `https://magnora-agentfirm.onrender.com`
   - `ANTHROPIC_API_KEY`: needed for Claude agents
   - `OPENAI_API_KEY`: only for Codex agents (may be left empty)
4. **Apply**. The first Docker build takes 10–20 minutes.

`BETTER_AUTH_SECRET`, `PAPERCLIP_SECRETS_MASTER_KEY`, and
`PAPERCLIP_TOOL_ACTION_SIGNING_SECRET` are generated by Render. Do not change
`PAPERCLIP_SECRETS_MASTER_KEY` later: stored secrets become unreadable.

On first boot Paperclip creates its tables in Supabase automatically.

## 3. Set the public URL

When the service is live, copy its URL from the top of the Render service page.
If it differs from the placeholder, update `PAPERCLIP_PUBLIC_URL` under
**Environment** and save (Render redeploys).

## 4. Claim the instance

1. Open the URL, create an account, and sign in.
2. Choose **Claim this instance**. You are now the instance admin.
3. Optional hardening once you are admin: add
   `PAPERCLIP_AUTH_DISABLE_SIGN_UP=true` under **Environment** so nobody else
   can create accounts (you can still invite people from inside Paperclip).

Do step 4 right after the first deploy: until the instance is claimed, the
first signed-in user can claim it.

## Plan and storage

- `plan: standard` (2 GB RAM). Agent CLIs run inside the container, and
  512 MB instances run out of memory.
- A 10 GB persistent disk is mounted at `/paperclip` for uploads and agent
  workspaces. Relational data lives in Supabase.
- Supabase free projects pause after a week of inactivity. Upgrade Supabase
  if agents should run unattended.
